#program nextdev
#autostart 10
10 REM nextdev - the Next half of the VS Code push-to-hardware loop.
20 REM Pairs with extra/Send-ToNext.ps1 on the PC. Save as autoexec.bas
30 REM in the root of the SD card (see extra/README.md) so every boot
40 REM re-enters the loop: ZX Next Remote soft-resets the machine when
50 REM it exits, which is exactly what closes this cycle.
60 REM
70 REM   no file waiting -> serve the bridge and WAIT for a push
80 REM   file waiting    -> move it aside (so it runs once) and run it
90 REM
100 REM The PC pushes to /dev/incoming.nex, then calls /forceexit: ZX
110 REM Next Remote leaves listen mode, ends its application and resets,
120 REM and the boot lands back here with a file waiting.
130 ON ERROR GO TO 200
140 REM Consume the push: the .mv both TESTS for the file and takes it
150 REM out of the way, so the next cycle listens again instead of
160 REM re-running the same build for ever. It errors when nothing
170 REM arrived, which is the branch to line 200.
180 .mv /dev/incoming.nex /dev/run.nex
190 .nexload /dev/run.nex: REM takes over the machine; never returns
200 REM Nothing waiting: hand the machine to the Listener and wait.
210 ON ERROR STOP
220 PRINT "nextdev: waiting for a push..."
230 .nexload /dev/zxnextremote-httpbridge.nex
240 REM Only reached if the .nex declined to start (wrong path, no
250 REM file): say so rather than spinning invisibly.
260 PRINT "nextdev: could not start the bridge flavour."
270 PRINT "Check /dev/zxnextremote-httpbridge.nex exists."
280 STOP
