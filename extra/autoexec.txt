10 REM nextdev - the Next half of the push-to-hardware loop.
20 REM Pairs with extra/PS-Send-ToNext.ps1 on the PC. This .txt is
30 REM the source; copy autoexec.BAS into /nextzxos/ (not the card
40 REM root) so every boot re-enters the loop.
50 REM
60 REM   no file waiting -> serve the Listener and WAIT for a push
70 REM   file waiting    -> move it aside (so it runs once) and run it
80 REM
90 REM Settings live in c:/nextzxos/autoexec.cfg, plain text written
100 REM by configuration mode at line 1000. A boot with no cfg goes
110 REM there; so does "b" at the overwrite prompt, holding B while
120 REM the machine boots, and anything the loop cannot find.
130 REM
140 REM ---- the rules this file is built on ------------------------
150 REM A .nexload that SUCCEEDS never comes back. Everything that
160 REM must happen has to happen BEFORE it: the previous build is
170 REM retired here, not tidied up "afterwards" - nothing written
180 REM after a .nexload runs when the build actually starts.
190 REM A dot command's failure is NOT reliably trappable. .mv raises
200 REM no BASIC error when its source is missing (checked on
210 REM hardware), so nothing below branches on a dot's success.
220 REM Each dot line is guarded first by OPEN # on the file it needs
230 REM (subroutine 8000): opening a MISSING file for input IS a
240 REM BASIC error, and BASIC errors do trap.
250 REM A dot cannot be handed a BASIC variable, and the .$ dot only
260 REM chains 8K dots - .mv and .sync5 are 24K dotN files - so the
270 REM configured folders are reached with CD and every dot line
280 REM below is a literal. No colon-tail on a dot line, and never a
290 REM dot after THEN: the tokeniser eats the argument.
300 REM ---- settings ----------------------------------------------

355 REM A cfg that failed validation has already been read into the
357 REM live variables, and configuration mode would write it straight
359 REM back. Put the defaults back first, so a single bad line is
361 REM repaired by pressing ENTER through rather than preserved.
363 IF ok=0 THEN GO SUB 9000
365 IF ok=0 THEN GO TO 1000
370 REM ---- the boot window ---------------------------------------
371 REM B, and not C or A: BOTH are taken by the Next's own boot
372 REM sequence (C picks a core), found the hard way on hardware -
373 REM a loop claiming either fights the machine underneath it for
374 REM the same keypress. Every prompt here names the same key.
375 REM
376 REM Say what is running, then watch for B for about two seconds.
377 REM A silent screen left the user with no sign that autoexec.bas
378 REM was running at all, so a machine switched to the boot menu
379 REM looked identical to a broken one. Short on purpose though:
380 REM this is on the path of EVERY boot.
381 CLS: POKE 23692,255

400 REM ---- consume a pushed build --------------------------------
401 REM Hold the ROM scroll counter open across the loop's own PRINTs.
402 REM Every pass, not once at boot: .sync5 saves SCR_CT on entry and
403 REM RESTORES it on exit, so the value it hands back is whatever
404 REM BASIC had before the session - which drains ~3 lines a pass and
405 REM stops with "scroll?" once the dot has filled the screen. The
406 REM saved value goes back before any dot runs, so nothing else
407 REM inherits a suppressed counter.
408 POKE 23692,255

445 REM A push is waiting. Retire last boot's build first, so that
450 REM run.nex only ever holds a fresh one and a push runs once:
455 REM   last boot's build -> last.nex  (kept, not destroyed:
460 REM                        .nexload last.nex re-runs it by hand)
465 REM   the new push      -> run.nex   (and is run below)
470 REM .mv is given -f because its own Overwrite (y/n) prompt has no
475 REM "b" and cannot be given one, so the question is asked here -
477 REM but only when retire is "ask" and only when last.nex really
479 REM would be overwritten.
480 LET a$=p$+"/run.nex": GO SUB 8000
485 IF e=0 THEN GO TO 530
490 LET a$=p$+"/last.nex": GO SUB 8000
495 IF e=0 THEN GO TO 525
497 IF r$="always" THEN GO TO 525
499 IF r$="never" THEN GO TO 530
500 PRINT "nextdev: Overwrite"
502 PRINT p$;"/last.nex (y/n/b) ?"
505 PRINT "y retires this build,"
507 PRINT "n discards it, b configures."
515 GO SUB 8800
517 IF k$="b" THEN GO TO 1000
519 IF k$="n" THEN GO TO 530
521 IF k$<>"y" THEN GO TO 515
525 .mv -f run.nex last.nex
530 .mv -f incoming.nex run.nex
531 REM Prove the MOVE happened, not merely that a run.nex is there.
532 REM On the discard paths (retire "never", or "n" above) the old
533 REM run.nex is still in place when 530 runs, so a .mv that failed
534 REM - and a dot's failure is not trappable - would leave LAST
535 REM boot's build sitting there for 545 to load, silently, for ever.
536 REM incoming.nex still being present is what says the move failed.
537 LET a$=p$+"/incoming.nex": GO SUB 8000
538 IF e=1 THEN GO TO 565
539 LET a$=p$+"/run.nex": GO SUB 8000
540 IF e=0 THEN GO TO 565
543 POKE 23692,sc
545 .nexload run.nex
550 REM Still here, so no build ran: nothing was waiting, the move
555 REM failed, or the build would not start - and a dot's failure is
560 REM not trappable, so this line must read true in every case.
565 PRINT "nextdev: no build ran - serving the Listener."
600 REM ---- hand the machine over and wait for a push -------------

635 IF e=1 THEN GO TO 650
640 GO SUB 8500
645 LET m$="": LET m2$=""

700 REM ---- the ZX Next Remote flavours ---------------------------

900 REM ---- switched off: hand the machine over -------------------
901 REM NextZXOS runs this program before anything else, so it cannot
902 REM stop itself from STARTING - "off" means it gives the machine
903 REM straight back instead of entering the loop, which is what
904 REM leaves you at the boot menu.
905 REM
906 REM The FLAVOUR is untouched by this, so switching back on does
907 REM not ask you to pick a transport again - it is a separate
908 REM setting for a separate question.
909 REM
910 REM ON ERROR is disarmed FIRST: an armed handler traps this very
911 REM STOP and would send the machine somewhere else entirely, the
912 REM trap this file's own rules warn about.
915 ON ERROR
920 PRINT "nextdev: loop switched off."
930 PRINT "hold ";: PRINT FLASH 1; INVERSE 1;"B";: PRINT " at the next boot"

9100 REM ---- is a$ an absolute path? ok=1 yes, ok=0 no --------------
9110 REM The loop CDs INTO the folder and also probes p$+"/file", so a
9120 REM relative name is applied twice: CD "push" then a look inside
9130 REM push/push, where nothing ever is. Absolute is the only form
9140 REM the two halves agree on, and the dot lines are literals that
9150 REM resolve against the CD - so this is checked at every door:
9160 REM here from the prompts, and again when the cfg is read.
9170 LET ok=0
9180 IF a$="" THEN RETURN
9190 IF a$(1)="/" THEN LET ok=1: RETURN
9200 IF LEN a$>1 THEN IF a$(2)=":" THEN LET ok=1
9210 IF ok=0 THEN PRINT "needs to start / or C: - not ";a$
